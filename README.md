# CS Gym – 作りながら学ぶCS基礎ロードマップ

このリポジトリは **「アプリを作りながら CS（Computer Science）の基礎を体系的に回収する」** ことを目的とした学習用プロジェクトです。
ここはChatGPTに書いてもらったよ。

単なるアルゴリズム演習や座学ではなく、

* **ビルドして**
* **実行して**
* **壊して**
* **直して**

という *実務に近いサイクル* の中で、CSの基礎概念を身体化することを目標にしています。

---

## 前提コンセプト

* 言語: **Kotlin (JVM)**
* ビルドツール: **Gradle**
* 形態: **CLIアプリケーション**

GUI や Web ではなく CLI を選ぶ理由は以下です。

* 入出力・処理・状態が明示的
* OS / ファイル / ネットワークと直接向き合える
* CS基礎（計算量・データ構造・I/O）が隠蔽されにくい

---

## 学習ロードマップ

### 0. 入門：ビルド・実行・入出力（最初にやる）

#### 目的

* 「プログラムは *入力 → 処理 → 出力* である」という原型を体に入れる
* ツールチェーン（Gradle / JVM / CLI）への恐怖を消す

#### 扱うトピック

* Gradle の役割（ビルド・実行の自動化）
* `./gradlew run --args="..."` による実行
* CLI 引数 (`args: Array<String>`)
* 標準入力 / 標準出力（`println`, `readLine()`）

#### できるようになること

* 「このアプリはどう起動されているか」を説明できる
* 実行時引数によって挙動が変わるプログラムを書ける

---

### 1. データ構造・アルゴリズム

#### 目的

* データの持ち方によって *できること・速さ* が変わる感覚を掴む
* 面接・実務で頻出の基礎を実装ベースで理解する

#### 扱うトピック

* コレクション

  * 配列 / List
  * Map（キーと値）
  * Set（重複なし）
* アルゴリズム

  * ソート（線形・比較）
  * 二分探索
* 抽象的データ構造

  * スタック（LIFO）
  * キュー（FIFO）

#### 計算量の導入

* O(n), O(log n) を **暗記せず** 感覚で理解
* 「要素が10倍になったら、処理時間はどうなる？」を考える

#### できるようになること

* 「なぜこの実装は遅いのか」を説明できる
* データ構造の選択理由を言語化できる

---

### 2. 文字列・パース（地味だが最重要）

#### 目的

* *仕様を満たす処理* を正確に書く力をつける
* 実務で最も遭遇する「データが汚い問題」に慣れる

#### 扱うトピック

* CSV / TSV の読み取り
* 入力値バリデーション
* 正規表現
* トークナイズ（分解・分割）

#### ポイント

* 「正常系」より「異常系」を意識する
* フォーマットが壊れている入力への耐性

#### できるようになること

* 仕様をコードに落とすプロセスを説明できる
* 曖昧な入力をどう扱うか判断できる

---

### 3. ファイルと OS

#### 目的

* プログラムが OS とどう関わっているかを理解する
* 永続化・ログ・失敗処理の基礎を身につける

#### 扱うトピック

* ファイル読み書き
* ディレクトリ探索
* ログ出力
* 例外処理（失敗を前提にした設計）

#### ポイント

* 「ファイルは常に存在するとは限らない」
* 「書き込みは失敗しうる」

#### できるようになること

* エラーを握りつぶさない設計ができる
* OS との境界を意識できる

---

### 4. テスト

#### 目的

* 変更しても壊れない安心感を得る
* 手動確認から脱却する

#### 扱うトピック

* Unit Test（JUnit）
* 正常系 / 異常系テスト
* テスト可能な設計

#### ポイント

* 「テストを書くために設計を改善する」
* コードの責務分離

#### できるようになること

* 変更に対する心理的コストが下がる
* 他人のコードを安心して触れる

---

### 5. ネットワーク入門

#### 目的

* 通信は *不確実* であることを前提に考える
* Web / API の基礎理解につなげる

#### 扱うトピック

* HTTP リクエスト（GET / POST）
* ステータスコード
* JSON パース

#### ポイント

* 通信は失敗する
* レスポンスは常に期待通りとは限らない

#### できるようになること

* API の挙動を冷静に扱える
* Web 系技術への橋渡しができる

---

### 6. DB 入門（必要に応じて）

#### 目的

* データ永続化と検索の仕組みを理解する

#### 扱うトピック

* SQLite による CRUD
* インデックス

#### ポイント

* 「なぜ検索が速くなるのか」を説明できること

---

### 7. 並行処理（余裕が出てから）

#### 目的

* 同時実行の難しさを *体験* する

#### 扱うトピック

* Kotlin コルーチン
* 並列 I/O
* スレッド安全性

#### 注意

* 早くやらなくていい
* 他の基礎が固まってからで十分

---

## このプロジェクトのゴール

* CS基礎を **断片知識ではなく構造として理解する**
* 「なぜそう設計するのか」を説明できる
* 面接・実務・設計の場面で *思考の土台* として使える

---

## 最後に

このプロジェクトは「最短で強くなる」ためのものではありません。

**「分かることを、分かる順番で積み上げる」** ための場所です。

焦らず、しかし確実に進めていきます。
